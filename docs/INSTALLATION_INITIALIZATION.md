# ERP installation initialization

A new PostgreSQL database is marked pending only when it contains no user tables, views, sequences, or foreign tables. The installer backs up the database before migration. It asks for the first administrator in a terminal; no default password or demo account is created. The password must contain at least 12 characters.

Initial settings, permissions, site catalogs, hosting defaults, and the administrator are created in a transaction. If initialization fails, the pending state remains and the installer can be run again. Registration is unavailable while initialization is pending. An existing database without the pending marker is not initialized by the installer.

Production Artisan commands that seed, wipe, reset, refresh, or roll back the database are blocked. The accounting chart seed endpoint is disabled in production. Schema migrations do not invoke seeders. When a legacy catalog migration is pending on an installation with users, it records a targeted upgrade task. After schema migration, `core:upgrade-legacy-installation` performs the pending metadata upgrade in transactions. Existing roles and their permissions, feature settings, site types, and packages are not overwritten. Missing roles receive permissions only when the role itself is newly created; no role is assigned to an existing user. New links for existing site types are optional and disabled by default. If a prerequisite such as an existing site category or a required feature is missing, the command fails and leaves the affected task pending for a retry after the prerequisite is repaired. Existing database backups are created before migrations. Restore and rollback procedures must preserve subsequent writes.

To check initialization against isolated disposable PostgreSQL databases, run `backend/tests/Integration/run-installation-check.sh`. The checks cover initialization rollback, an HTTP login, migration replay, production command guards, and administrator setup through an interactive terminal. The script uses a private Docker network and dedicated test databases. It requires Python 3, the backend test image, and the PostgreSQL 15 image locally. It does not connect to a production database.
